# Restaurant Vlog Skill

这是 `youtube-video-editor` 的探店 Vlog 上层 Skill。核心原则是：**先讲故事，再剪镜头；Auto-Editor 只负责机械性工作，不负责决定故事。**

## 1. 两种模式

### A. 拍摄前：脚本 + Shot List

当用户还没拍摄时，先输出一份可现场执行的拍摄计划，默认包含：

1. 5–10 秒开场钩子
2. 门头/街景/到店
3. 店内环境与氛围
4. 菜单、价格、特色菜
5. 点单过程
6. 厨房/制作过程（允许拍摄时）
7. 上菜
8. 每道菜的 Hero Shot
9. 切开、夹起、拉丝、流心、冒热气等质感镜头
10. 第一口真实反应
11. 味道、口感、分量、价格评价
12. 总结与是否值得来

默认给出：
- 口播文案
- 对应 B-roll
- 景别（广角/中景/近景/特写）
- 建议时长
- 必拍/可选
- 现场收音提醒

除非用户明确要求，不要把整条 Vlog 写成僵硬广告词；保留现场感和真实反应。

### B. 拍摄后：素材分析 + 自动剪辑

用户提供素材文件夹后：

1. **先扫描，不直接删除。**
2. 用 FFprobe 建立素材清单：文件名、时长、分辨率、帧率、音轨。
3. 对含人声素材优先用本仓库 whisper.cpp 生成转录。
4. 按语义把素材归类：
   - storefront：门头/街景/到店
   - ambience：环境/装修/座位/客流
   - menu：菜单/价格/点单
   - cooking：制作过程/厨房
   - serving：端菜/上桌
   - food-hero：完整菜品特写
   - texture：切开/夹起/蘸酱/拉丝/流汁/热气
   - host-talk：人物口播
   - tasting：试吃/第一口/表情
   - verdict：总结/价格/推荐
   - unusable：严重模糊、遮挡、误触、纯黑、明显失败镜头
5. 建立 `edit-plan.md` 后再执行剪辑。
6. 原始素材一律保留，不覆盖。

## 2. 镜头选择规则

同类镜头出现多个版本时，按以下顺序选：

1. 内容价值：是否真正说明了食物、店铺或体验
2. 清晰度/对焦
3. 稳定性
4. 曝光和白平衡
5. 构图
6. 食物主体占比
7. 动作完整性
8. 与前后镜头是否重复

不要因为某镜头安静就删除。探店 Vlog 中，以下无对白片段通常应保留：
- 食物刚上桌
- 切开/拉丝/冒热气
- 倒酱/蘸料
- 环境 establishing shot
- 厨房动作
- 第一口之前的停顿
- 能明显制造期待的反应镜头

## 3. 默认故事结构

默认按下面结构组织，但可以根据素材调整：

```
Hook
→ 到店
→ 为什么来/有什么特别
→ 环境
→ 菜单与点单
→ 等待/制作
→ 上菜
→ 逐道试吃
→ 价格与分量
→ 总结
```

开头 15 秒内尽量出现：
- 最诱人的食物镜头，或
- 最有反差的一句评价，或
- 最有信息量的价格/特色。

不要长时间从走路、停车、找店开始，除非这本身是故事的一部分。

## 4. 口播与 B-roll 规则

人物连续说话超过约 8–12 秒时，优先寻找语义相关 B-roll 覆盖，但保留原始人声。

举例：
- 说“这家开了30年” → 门头/老照片/店内
- 说价格 → 菜单/账单/菜品
- 说“外皮很脆” → 切开、夹起、咬下的近景
- 说环境 → 环境广角与细节

避免为了“有画面”而插入无关 B-roll。

## 5. 节奏

默认成片目标：自然、真实、食物优先，不剪成纯快节奏广告。

推荐：
- Hook：0.5–2 秒/镜头
- 环境：1–3 秒/镜头
- 食物 Hero Shot：1.5–4 秒
- 关键制作动作：按动作完整性保留
- 人物口播：去掉明显口误和过长空白，但保留自然呼吸
- 第一口反应：不要过度 jump cut

如果用户没有指定时长：
- 短视频：60–120 秒
- 标准探店 Vlog：3–5 分钟
- 深度探店：6–10 分钟

## 6. 自动剪辑工具调用

### Auto-Editor
只用于：
- 明显死空气
- 口播中无意义超长停顿
- 明显失败 take 的初筛

必须 **Preview → 检查 → Render**。

不得仅按音量阈值处理整条 Vlog，因为无声食物 B-roll 是有效内容。

### Whisper
用于：
- 建立讲话素材索引
- 找口播关键词
- 生成中文字幕

中文默认 `Language zh`。
字幕先生成 SRT，再抽查后烧录。

### FFmpeg
用于：
- trim / concat
- crop / resize
- speed
- audio normalization
- BGM mixing / ducking
- subtitle burn-in
- final render

遵循根目录 `SKILL.md` 的安全与验证规范。

## 7. BGM 与同期声

优先级：
1. 人声
2. 食物/环境关键同期声
3. BGM

BGM 在人物讲话时自动 ducking。
以下镜头可适当提高同期声存在感：
- 油炸
- 铁板滋滋声
- 切脆皮
- 倒汤
- 拉丝
- 咬脆食物
- 咖啡机/厨房动作

不要让 BGM 覆盖这些声音。

## 8. 字幕

默认：
- 中文字幕
- 口语化断句
- 每条尽量短
- 不把字幕挡在食物主体上
- 人物口误若已从成片剪掉，字幕同步删除

只有用户明确需要时才做中英双语字幕。

## 9. 输出物

完整任务默认生成：

```
output/
  final-vlog.mp4
  edit-plan.md
  transcript.srt
  shot-index.md
```

如果用户只要求粗剪，则优先输出：
- `rough-cut.mp4`
- `edit-plan.md`

## 10. edit-plan.md 格式

每个片段记录：

```
序号 | 类型 | 源文件 | In | Out | 使用理由 | 音频 | 备注
```

并在顶部写：
- 目标时长
- 故事线
- Hook
- 关键菜品
- 需要人工确认的问题

## 11. 拍摄前 Shot List 模板

拍摄前可直接使用本仓库：
`restaurant-vlog/SHOT-LIST-TEMPLATE.md`

## 12. 验收

成片完成后至少检查：

- [ ] 开头 15 秒有明确看点
- [ ] 门头/店铺身份清楚
- [ ] 菜单或价格信息可理解
- [ ] 主打菜都有完整 Hero Shot
- [ ] 重要味觉评价都有对应画面
- [ ] 第一口反应没有被误剪
- [ ] 无明显重复镜头
- [ ] 无严重糊焦/误触素材
- [ ] 字幕与声音同步
- [ ] BGM 不压人声
- [ ] 食物关键同期声得到保留
- [ ] 结尾给出清晰总结
- [ ] 原始素材未被覆盖

## 13. 对 Codex 的执行指令

当用户说“按探店 Vlog skill 剪”“restaurant vlog”“探店素材”时：

1. 先读取本文件。
2. 再按任务读取根目录 `SKILL.md` 与必要的具体工作流文件。
3. 拍摄前任务只做策划，不运行视频处理。
4. 拍摄后任务先生成素材索引和 `edit-plan.md`。
5. 用户没有要求“直接成片”时，优先先做粗剪。
6. 所有自动删除/跳剪策略必须保护无声 B-roll。
